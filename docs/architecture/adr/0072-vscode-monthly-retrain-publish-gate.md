# ADR-0072 — vscode monthly retrain: rolling window, same-holdout champion gate, human-merged publication

Status: Proposed (GG decision G4, `docs/DECISION_LOG_2026-10.md` D88: build vscode monthly retraining at zero cost, with a publish gate that refuses a worse model)
Date: 2026-10-29
Decider: Gaurav Gandhi (G4); design by the unattended run, open to review

Implements the "Scheduled retraining (design only)" section of ADR-0070. Code: `scripts/vscode_retrain.py`, `scripts/vscode_retrain_lib.py`,
tests `tests/test_vscode_retrain.py`. The scheduled workflow is a separate PR for GG (no workflow file lands with this ADR).

## Context

The served vscode classifier scores 4.4% strict top-3 on 2026 issues; the ADR-0070 family-only TF-IDF+LR retrain scores 36.4% on the same test
(D85, `reports/qp1_vscode_phase1_2026-10.json`). The vocabulary drifts (ADR-0070 section (b): a frozen class list loses 5-14 coverage points
per quarter). A model that is retrained must not silently replace a better one, and nothing may reach production without a human merge.
Constraints: $0 (no paid service, no billable GCP), CPU only, deterministic (seed 42), the existing manifest/GCS publication path
(`data/models/MANIFEST.sha256`, `scripts/publish_models.py`, `scripts/verify_model_manifest.py`, deploy pull) stays the only way a model is served.

## Decision

1. **Data window (as of the run date `T`).** Labels settle: only issues created on or before `cutoff = T - 30 days` are used (ADR-0070 section
   "Scheduled retraining": labels settle within 30 days). Population = issues with >= 1 non-excluded label at their final state, regardless of
   open/closed state (the ADR-0070 population; the label, not closure, is what is learned). Start = `max(2023-01-01, cutoff - 48 months)`:
   ADR-0070 showed shorter windows lose coverage, so the window grows from the 2023 floor and rolls only after 48 months (the 48 is a
   budget/age choice, untested beyond the 2023 floor). Input = the incremental scraper's `derived_v2` tables (`issues.parquet`,
   `label_events.parquet`); the retrain makes no network calls. A stale or missing scrape shows up as a small holdout and the gate refuses.
2. **Split by time, half-open on `created_at` (UTC):** train `[start, cutoff-120d)`, calibration `[cutoff-120d, cutoff-60d)`, holdout
   `[cutoff-60d, cutoff)`. Calibration/holdout issues whose `text_hash` occurs in an earlier split are dropped (the leakage rule of
   `qp0_make_splits.py`, text-hash part only; the duplicate-pair flag is not recomputed here). The holdout is the newest settled data and is
   never used for fitting, selection, tau or conformal calibration.
3. **Model: the ADR-0070 family-only TF-IDF+LR recipe unchanged** (word 1-2 grams, min_df 2, sublinear, 200k features; multinomial LR fit
   on non-`other` issues; C x class_weight grid of 8). Classes are regenerated by the frozen exclusion/prefix rules on the train window
   (parents carried by >= 30 train issues, `other` last) and the class-list sha256 is logged; the rules themselves change only by ADR.
   Grid winner = highest strict top-3 on calibration, tie smaller C. Abstention tau = calibration max-probability quantile maximising abstention
   F1. Conformal (ADR-0071 method family, alpha 0.05): score picked by the ADR-0071 rule on calibration, qhat from the in-family calibration set.
   Fit on train only (not train + calibration) so tau and qhat stay valid for the saved model.
4. **Eval gate (pre-declared, in `gate_decision`).** The challenger and the current champion are scored on the SAME holdout rows in the SAME
   class space (the challenger's regenerated list; a champion class outside it maps to `other` via `parent_of`, so champion staleness costs
   it coverage, which is the real drift cost). Headline = strict top-3 (ADR-0070 decision 4). 2000-resample paired bootstrap, seed 42.
   **Accept only if all hold:** (a) paired difference vs champion >= +0.01 absolute AND its 95% CI lower bound > 0; (b) paired CI lower bound
   vs the naive train-prior baseline > 0; (c) in-family top-3 not worse than the champion by more than 2 points (CI lower bound > -0.02);
   (d) holdout >= 500, train >= 5000 issues, >= 20 classes. Equal, worse, noisy or tiny-sample challengers are refused. Fail closed: a missing,
   non-numeric or NaN input, an unreadable intermediate file, or any exception yields `refuse` (exit 10) or error (exit 2), never a pass; the
   staging step re-checks that the gate file says `accept` for the sha256 of the exact candidate file.
5. **Decision record.** `gate_decision.json` holds decision, per-check results, thresholds, all metrics with CIs, class-list hash, window
   boundaries, sha256 of the input tables and of the train/calibration/holdout issue-number lists, champion sha256, candidate sha256, seed.
6. **Where compute runs ($0).** On a public repo, GitHub Actions free minutes (`ubuntu-latest`, 4 vCPU, 16 GB RAM, 6 h job limit); or
   locally. Measured dry run (this laptop, CPU, 4 threads, `CUDA_VISIBLE_DEVICES=-1`, 30,205 train issues): 66 min wall, dominated by the
   8-fit grid; free RAM fell by about 6 GB while it ran (peak not measured). Budget: < 8 GB RAM, < 120 min (job `timeout-minutes`).
   The derived tables (a ~140 MB scrape output) are not in git; the workflow PR defines how they reach the runner (a cached scrape artifact),
   and a run without them refuses. No GCS, Kaggle, Groq or paid service is used.
7. **Publication (never automatic).** An accepted candidate is written only to `<out>/staging/`: the bundle
   `component_classifier_microsoft_vscode_family_v2_<T>.joblib`, `MANIFEST.sha256.candidate` (current manifest plus one line; the champion line
   is kept), `manifest.diff`, `candidate_metadata.json` (holdout/naive/champion metrics, `model_beats_naive`, class-list hash, gate-file hash).
   The scheduled workflow uploads these as workflow artifacts and opens a PR containing the manifest change for a human to review and merge.
   Uploading to GCS (`publish_models.py`) and the deploy stay manual and unchanged. Serving the new bundle format additionally needs a loader
   in `component_classifier.load_classifier` (the served pickle is the OVR format), which is a separate, reviewed change; until then a
   merged candidate is inert.
8. **Rollback.** The champion artifact and its manifest line are never removed by a retrain; rolling back is reverting the manifest PR (and, if
   already served, redeploying the prior revision by the existing path). A refused run changes nothing.
9. **Out of scope:** k8s retraining (resolution/priority models, their own ADRs), embedding or fine-tuned models and indexes (GPU quota),
   changing the exclusion list or prefix list, the drift-triggered weekly check of ADR-0070 (calendar cadence only here), enabling serving.

## Consequences

- A worse model cannot be staged: the worst case of a bad month is a refused run and an unchanged champion. The gate's price is that a real
  small improvement (< 1 point) is also refused; the margin is a pre-declared constant, changed only by editing this ADR.
- The first champion is the served OVR model (4.4% strict top-3 on 2026 test), so the first accepted challenger is expected; later months
  compare against the previous retrain bundle (`--champion` accepts either).
- The holdout moves every month, so metrics are not comparable across runs and are not published as test results; the ADR-0070 test numbers
  remain the only published test figures. The gate is a regression/promotion check on 60 days of data, not a new benchmark.
- Open-set share still caps the strict metric by coverage; the gate compares like with like but does not raise the ceiling.
- Quiet months (a few hundred labelled issues in the holdout) may fall under the size floor and refuse; that is intended.
- The regenerated list can admit labels the frozen exclusion list never saw (the dry run produced 121 classes including `ai-generated`,
  `ai-triaged`, `2026-themes`). The rule is not hand-edited; such labels are surfaced in `train_info.json` and need an exclusion-list ADR.
- Honest limits: the 30-day settle lag, the 48-month roll, the 1-point margin and the 60-day holdout are design choices, not tuned on data.

## Alternatives

- **Promote on any improvement / on point estimate:** rejected, noise on ~1-2k holdout issues is several points.
- **Compare against the champion's own historical report:** rejected, different populations; the SAME-holdout comparison is the only fair one.
- **Fixed 2025-style train/validation/test splits:** rejected for the loop (the test period would be stale after a month); they remain the
  published benchmark.
- **Auto-upload and auto-deploy on accept:** rejected (G4: human merge; CLAUDE.md rule 31a: production changes do not come from automation
  without review).
- **Paid or GPU retraining (Kaggle, cloud):** rejected, TF-IDF+LR fits on a CPU runner; GPU quota is already contended.
- **Weekly drift-triggered retrain:** deferred, adds a metric and a trigger to maintain; monthly is the cadence ADR-0070 justified.
